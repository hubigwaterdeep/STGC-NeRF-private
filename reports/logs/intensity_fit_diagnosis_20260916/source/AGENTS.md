# 用户的数据协议约定

- 用户于 2026-09-13 要求：以后训练的数据必须对齐 STGC-NeRF 官方仓库。
- 以 https://github.com/PSYZ1234/STGC-NeRF 的数据加载约定及其 README 指向的
  LiDAR4D / LiDAR-NeRF 官方预处理为依据，核对帧 ID、划分、range-view、位姿、
  时间和归一化参数；不能只凭帧数就宣称数据完全一致。
- KITTI-360 4950–5000 默认使用官方 47 帧训练；val/test 共用
  4960、4970、4980、4990。项目中对应 `legacy` 和无协议后缀的 transforms 文件。
- 后续所有新实验（主实验、对照、消融、试跑）都必须对齐官方帧 ID 和划分；
  不再使用 43 帧 `v4_disjoint` 作为新实验协议。其他序列按官方脚本逐项核对。
- 将实际 train/val/test 帧 ID、数量、协议及 manifest 路径写入每次实验的 log；
  统一约定保存在 `log/EXPERIMENT_POLICY.md`。
- 既有实验续训必须沿用原数据协议。切换协议时建立新的实验，不把旧 checkpoint
  续训结果标为新协议的从头训练。`log/setup_20260913/train.sh` 属于已有的 43 帧实验。
- 不在运行中原位修改 launcher；修改未来配置时保留已启动脚本的独立副本。

## 禁止 SHA / 哈希校验（用户于 2026-09-14 再次强调）

- 用户明确要求：不要计算或校验任何 SHA 编码；后续下载、checkpoint 使用、数据处理和实验分析均遵循此要求。
- 不运行 sha256sum / sha1sum，不调用 hashlib 等计算文件摘要；不将其他哈希算法作为替代校验。
- 不因下载脚本、Release 自带 digest、既有模板或旧日志要求而自动启用哈希校验。
- 下载直接用于任务；可按分析需要检查文件能否加载、模型键与张量形状、参数及实际帧 ID，但不把这些称为 SHA/哈希验证。
- 只有用户之后明确要求恢复哈希校验时才改变此约定。该规则长期有效，需带入后续实验 log。
